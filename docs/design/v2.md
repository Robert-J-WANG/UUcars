# UUcars Marketplace V2 Design

## Purpose

Extend the V1 API into a publicly accessible full-stack marketplace. Complete
account recovery and transaction workflows, provide a React interface for each
user role, and establish Azure hosting. V2.0 delivers the application and
deployment; V2.1 refines its visual consistency and responsive behaviour.

## Scope

- Email verification, password reset and transactional email.
- Vehicle image upload to Cloudflare R2.
- Seller confirmation of order completion, buyer reviews and seller ratings.
- Public browsing, account pages, seller tools, personal views and Admin moderation.
- Azure production hosting and GitHub Actions deployment.
- Shared design tokens, responsive navigation and vehicle cover images.

Retain the existing backend layers and business rules. Background processing,
refresh-token rotation and real-time notifications are outside this version.

## Key design decisions

### Accounts and external services

Use separate, time-limited, one-use tokens for email verification and password
reset. Require verification before password sign-in, and return a uniform
forgot-password response to avoid disclosing whether an account exists.

Access Resend through an email-service interface so tests can replace delivery.
Upload vehicle images to R2 through its S3-compatible API, validate size and
MIME type, and generate unique object names. Restrict image management to the
owning seller's draft listings.

### Transaction completion and reviews

Allow the seller to complete a pending order. Only its buyer may review the
completed transaction, with a unique order constraint preventing repeat reviews.
Derive the reviewed seller from the order and expose public rating summaries.

### Frontend responsibilities

Use React and TypeScript with central React Router definitions. TanStack Query
manages server data, Zustand holds authentication state, and React Hook Form
with Zod handles forms. Keep shared types aligned with backend DTOs.

Axios attaches credentials and normalises HTTP failures; feature API modules
unwrap response data. Mutations invalidate the affected query keys so listing,
favourite and order views reflect completed operations.

Store search filters and pagination in the URL for repeatable, shareable results.
Provide explicit loading, empty, failure and success states. Route guards and
role-based navigation guide users, while API authorisation remains authoritative.

### Interface consistency

Use Tailwind CSS and shared UI components for forms, cards, tables and feedback.
V2.1 consolidates colours, typography, spacing and responsive layouts into a
common design system. List responses supply a cover-image URL so vehicle cards
can render imagery without fetching each vehicle's full details.

### Production hosting

Host the React build on Azure Static Web Apps, the API container on Azure
Container Apps and relational data in Azure SQL Database. R2 and Resend provide
media storage and email delivery.

Supply public frontend values at build time and backend credentials at runtime.
Configure explicit CORS origins and SPA navigation fallback. GitHub Actions
publishes and deploys the application, using OIDC for Azure backend deployment.

## Delivery phases

| Phase | Outcome |
|---|---|
| Backend extensions | Email workflows, image storage, order completion and reviews |
| Frontend foundation | Typed API access, shared components, authentication state and routing |
| Marketplace journeys | Browsing, filtering, details, favourites, seller tools and order views |
| Administration | Role-protected moderation and consistent error feedback |
| Production delivery | Azure resources, environment configuration and automated deployment |
| Interface refinement | V2.1 design tokens, responsive navigation and vehicle imagery |

## Validation and acceptance

Extend backend verification for account tokens, ownership and transaction rules.
Check frontend builds and browser journeys across anonymous, buyer, seller and
Admin roles. Verify external integrations and configuration in the hosted system.

Acceptance requires:

- registration, verification, sign-in and password recovery form a complete flow;
- image operations enforce ownership and upload limits;
- only the seller completes an order and only its buyer reviews it once;
- frontend mutations refresh relevant data and failures provide useful feedback;
- production routes, CORS, email links and image URLs work together;
- responsive interface changes preserve the established business journeys;
- deployment credentials and runtime secrets remain outside the repository.
