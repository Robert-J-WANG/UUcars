## Git 分支策略

### 分支结构

```text
main       ← 正式里程碑版本，打 Tag
develop    ← 日常开发基准分支
feature/*  ← 独立模块或阶段分支
```

### 标准 Feature 工作流

```bash
# 1. 从最新 develop 创建功能分支
git checkout develop
git pull origin develop
git checkout -b feature/xxx
git push -u origin feature/xxx

# 2. 开发过程中按功能单元提交
git status
git add .
git commit -m "feat: ..."
git push origin feature/xxx

# 3. 阶段完成后合并回 develop
git checkout develop
git pull origin develop
git merge --no-ff feature/xxx \
  -m "merge: feature/xxx into develop"
git push origin develop

# 4. 删除已经完成的功能分支
git branch -d feature/xxx
git push origin --delete feature/xxx
```

### Commit Message 约定

```text
init:     项目初始化
feat:     新功能
fix:      Bug 修复
test:     测试
refactor: 重构但不改变功能
chore:    配置、依赖和脚本
docs:     文档
merge:    分支合并
release:  里程碑发布
```

### V1 里程碑计划

```text
v0.1  Step 07 完成
      项目、配置、工程基础设施和数据库就绪

      用户、车辆、收藏和订单核心业务就绪
```

# HTTP 状态码约定

```text
200 OK
查询或操作成功

201 Created
资源创建成功

204 No Content
删除成功且不返回响应体

400 Bad Request
请求格式错误或业务前置条件不满足

401 Unauthorized
未登录、Token 缺失或 Token 无效

403 Forbidden
用户已经登录，但没有对应操作权限

404 Not Found
资源不存在，或资源不应向当前用户暴露

409 Conflict
重复资源或资源状态冲突

500 Internal Server Error
未预期的服务器错误
```
